# 0008 Rust for the daemon and CLI

Status: accepted (supersedes 0001; amends 0002); crate list amended by 0009 (tungstenite)

## Context
ADR 0001 recommended Go. The VM has no Go toolchain; it has a Rust toolchain (cargo 1.95) and
the user chose Rust for Phase 1. A TypeScript prototype validated the discovery design on real
data, but it needs Node from nvm at runtime, which stations must not depend on.

## Options
1. Go, as in 0001 (toolchain absent on the VM).
2. TypeScript on Node or Bun (runtime dependency on every station).
3. Rust: one binary per target, no runtime dependency.

## Decision
Option 3. Crates are limited to `rusqlite` (feature `bundled`), `serde` and `serde_json`, all
vendored in `~/.cargo/registry` and built with `--offline`. ULID, RFC 3339, ticket matching,
remote URL normalisation and shell quoting are hand-written and unit-tested
rather than adding `ulid`, `chrono`, `regex`, `url` or `shlex`.

## Consequences
- Build machines need a C compiler (bundled SQLite). Stations need nothing.
- macOS binaries are built on a Mac or in macOS CI; no cross-compilation in Phase 1.
- Contract types are written by hand with `serde_json::json!`; the contract test checks the
  `--json` output against `contract/schemas/line.schema.json` (required, properties, enums).
- macOS process probing (`ps -o args=`, `lsof -d cwd`) is implemented but not run on a Mac yet;
  on macOS `procStart` is not compared because its format there is unverified.

## Amendments to 0002
- State dir: platform dir (`$XDG_STATE_HOME/overseer` or `~/.local/state/overseer`,
  `~/Library/Application Support/overseer` on macOS); `OVERSEER_STATE_DIR` overrides it.
  The in-checkout wrapper `bin/overseer` defaults it to `<repo>/.state` for development. Dir `0700`, `overseer.db` `0600`, created with explicit modes.
- Driver: `rusqlite` with bundled SQLite instead of `modernc.org/sqlite`. Default rollback
  journal while `ls` is the only writer; WAL when the daemon becomes long-running.
- Codex `state_N.sqlite`: opening the live file, even with `mode=ro`, creates or writes its
  `-shm` because the database is in WAL mode. Overseer copies `state_N.sqlite` and `-wal`
  into `<state>/tmp/codex-<pid>/`, opens the copy, and deletes it after the query. The query
  uses an explicit column list and never reads `title`, `first_user_message` or `preview`.
  Fallback: `session_meta` (first line) of `sessions/YYYY/MM/DD/rollout-*.jsonl`.
