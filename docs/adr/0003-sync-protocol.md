# 0003 Sync protocol (daemon to API)

Status: accepted, refined by 0009

## Context
Stations dial out over NetBird; the API never dials in. Daemons go offline for hours.

## Decision
One WebSocket per station: `GET /v1/stations/{id}/sync`, bearer station token.
Frames in `contract/schemas/sync-message.schema.json`:
- Daemon sends `hello{lastAckedSeq}`; API replies `ack{seq, resync?}`.
- If `resync` or first connect: daemon sends `snapshot{seq, lines}`; API replaces that station's lines
  (lines missing from the snapshot are kept as history, not deleted, unless already `hung-up`).
- Otherwise daemon replays its outbox from `lastAckedSeq+1` as `delta{seq, upsert, remove}`.
  API applies a delta only if `seq == last+1` (else asks resync); upserts are keyed by `line.id`, so
  replays are idempotent.
- `heartbeat` every 15 s with active count and memory; station offline after 3 missed heartbeats
  (45 s) → `station.offline` event.
- Commands: API → `command{…}`, daemon → `command_result{…}`, keyed by command id (idempotent).

## Consequences
No broker. A 10-minute outage is a replay of the outbox; a lost outbox costs one snapshot.
Line ids are generated by the daemon (ULID prefixed by station id) so they are globally unique without coordination.
